# M0 Spikes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the numbers that decide the product shape — ASR real-time factor, battery per hour, diarization accuracy, and foreground-service survival on a Samsung and a Chinese OEM ROM — behind a scaffold that CI can build.

**Architecture:** One Gradle module with packages (`capture`, `asr`, `speaker`, `spike`). A single `microphone` foreground service owns `AudioRecord`; a 60 s ring buffer feeds Silero VAD and sherpa-onnx. Spikes are throwaway measurement screens, not product UI.

**Tech Stack:** AGP 9.4.1, Gradle 9.8.2, built-in Kotlin (no `org.jetbrains.kotlin.android` plugin), Jetpack Compose (BOM 2026.09.00), sherpa-onnx 2.0.0 AAR, minSdk 26 / compileSdk 37 / targetSdk 36, JVM 17.

**Spec:** [docs/DESIGN.md](../DESIGN.md) and [docs/PLAN.md](../PLAN.md) §5 M0.

## Global Constraints

- Application ID and package: `io.github.markyu0401.everheard`.
- `compileSdk = 37`, `targetSdk = 36`, `minSdk = 26`, JVM target 17.
- AGP 9.4.1 / Gradle 9.8.2 with built-in Kotlin: do not apply `org.jetbrains.kotlin.android`.
- Never commit model weights, audio, API keys, keystores, device serials, or personal paths.
- Capture is visible: persistent notification, start tone, live screen. No covert path.
- Every task ends with `./gradlew lint testDebugUnitTest assembleDebug` green and a commit.
- Measurements use the protocol in DESIGN.md §12: 30 min, screen off, 50 % brightness, 3 runs, median.
- Battery and accuracy figures are measurements, not claims; report the raw numbers in the spike report.

## Review Focus

These are the conditions most likely to break a real user in M0; each is pinned by a test in the task that owns the code.

1. **Background start of the microphone service** → must throw/deny and fall back to a notification, never crash the app. (Task 3)
2. **Screen-off OEM kill** → the service must survive 4 h on both ROMs or the failure must be documented with a recovery path. (Task 8)
3. **Corrupt/missing model download** → ASR must fail closed with a readable error, not a native crash. (Task 6)
4. **Quiet or fast speech missed by VAD** → speech ratio must stay within ±10 % of manual labels, and min-speech/hangover must be configurable. (Task 5)
5. **Wrong battery methodology** (screen on, charging, one run) → the harness must assert screen-off and unplugged, and take the median of three. (Task 8)
